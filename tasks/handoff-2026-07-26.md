# Handoff — Stage 81 当前态操作者待办与审批集合

> 日期：2026-07-26
> 状态：已完成并通过完整验证

## 当前结果

Stage 81 已实现 current-state、fixture-backed 的操作者待办和审批集合投影。它读取当前 blocked Run fixture，只聚合最新 attempt/review/handoff，区分 1 个当前合格 cancel、1 个 pending approval 和 4 个 blocked/stale action。

历史 checkpoint 资格不会自动成为当前资格；属于旧 attempt 的 review、旧 handoff 或旧 attempt retry 会被标记为 `target_not_current` 或状态阻止。

安全边界保持不变：`execution_authorized=false`、`dispatch_eligible=false`、`execution=not_executed`；不读取真实 approval ledger，不调用 Agent，不启动 session，不探测 readiness，不访问网络，不写 ledger。

## 下一里程碑上下文：Stage 82

长期产品目标已经冻结在 `docs/130-gui-first-external-agent-control-plane-target.md`：本项目是 GUI-first、本地优先的外部 Agent Harness / Control Plane，不是另一个聊天 Agent，也不重做 Claude、Kimi、OMP/Pi、QwenPaw 的模型、session 或工具系统。

Stage 82 定义为 **External Agent Adapter Contract 与 MVP Boundary**。恢复后先完成 design-only 输出：

1. identity、adapter、transport、version 和 capability 的稳定身份；
2. readiness evidence 的来源、TTL、binding 和 fail-closed 语义；
3. 外部 session 与 Harness run/attempt 的映射；
4. 结构化 work-item dispatch envelope，禁止任意 argv/cwd/env 旁路；
5. ordered event、deduplication、disconnect 和 outcome-unknown recovery；
6. cancel、artifact、review、retry 和 terminal audit 契约；
7. approval evidence 的 issuer/operator、target、expected state、撤销、过期、binding drift 和 idempotency；
8. ACP、CLI、local process 等 transport 的共同上层语义；
9. GUI 展示真实 Agent 状态、任务、事件、审批和 artifact 所需的最小 live read model；
10. MVP 验收线：至少三类外部 Agent implementation，以及一条 Planner -> Executor -> Reviewer 真实闭环。

Stage 82 的明确停止线：

- 不调用 Agent、启动 session 或探测 live readiness；
- 不读取或修改真实 approval ledger；
- 不新增第三个真实 operation；
- 不实现网络 adapter、服务、数据库或后台任务；
- 不把 ACP、QwenPaw 或任一单一 Agent 写成系统核心；
- 不增加 Agent-specific 主流程或 Control Panel 专用分支；
- 不把 preview、readiness、fixture approval、业务资格或 current inbox 解释为执行授权。

Stage 82 第一交付物应是独立设计和测试计划。真实 adapter、dispatch 或桌面端实现必须在 design gate 完成后再次获得用户明确授权。
