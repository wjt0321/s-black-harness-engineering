## 下一阶段启动上下文

### 目标

在现有协作计划、单工作项执行、不可变证据和人工审阅基础上，设计并实现一次**有限的规划者 → 执行者 → 审阅者闭环**。这不是自治循环：每个角色只允许一个有界轮次，每次角色交接都需要人工确认，任何失败或“要求修改”都停止当前链路。

### 建议的最小闭环

1. 操作者提交一个有界目标，并选择固定角色映射。
2. 规划者在无工具会话中只生成结构化计划候选，不执行任务。
3. Harness 校验计划结构、依赖、角色绑定、预期产物和审阅门；操作者确认后才允许进入执行。
4. 执行者只执行一个已确认工作项，继续复用阶段 87 的固定派发和阶段 88 的真实事件、不可变产物与审计。
5. 操作者确认将精确证据交给审阅者。审阅者只产生结构化审阅建议，不修改产物、不再次执行。
6. 最终“通过/要求修改”仍由人工提交；“要求修改”保留旧证据并停止，不自动重试。

### 明天首先需要冻结的设计问题

- 只有 Pi 和 OMP 两个真实宿主时，三个角色如何固定映射；是否允许同一宿主在不同、串行尝试中承担两个角色。
- 规划者输出 JSON 的固定 schema、字节上限、允许字段和敏感信息扫描规则。
- 审阅者输入只允许哪些证据摘要与安全产物内容，以及审阅建议 JSON 的固定 schema。
- 三个角色之间需要几个一次性人工确认摘要，以及每个摘要必须绑定哪些计划、尝试、产物和状态证据。
- “要求修改”是否只结束当前链路；建议本阶段不增加自动重试，新的执行必须由操作者重新确认。
- 如何在现有控制面板中同时展示角色、当前门禁、真实尝试、产物、审阅建议和最终人工决定。

### 必须复用

- `adapters/collaboration-plan.schema.json` 与现有协作计划校验；
- `agent_runtime/orchestration_single_work_item_execution.py` 的单工作项派发、租约和审计；
- `agent_runtime/external_agent_evidence_store.py` 的不可变证据与固定恢复；

- Pi/OMP 固定状态和派发绑定，不新增第三个宿主或通用适配器执行。

### 继续禁止

- 任意 shell、argv、cwd、env、网络、Agent 文件或 MCP 工具；
- Harness 启动、关闭或重启外部 Agent；
- 多工作项、并行角色、自动重试、无限循环和跨 Agent 自由对话；
- Agent 指定任意项目文件作为输入或产物；
- 自动采纳规划者计划、自动采纳审阅者建议或自动提交最终决定；
- 数据库、常驻服务和 QwenPaw 接入。

### 建议验收标准

- Pi/OMP 完成一条真实、串行、三角色链路；每个外部轮次都有独立尝试、固定事件和不可变证据。
- 规划候选、执行产物、审阅建议和最终人工决定能够在新 CLI 进程中恢复读取。
- 每次角色交接的确认摘要发生任何漂移时失败关闭。
- “要求修改”路径停止且不自动重跑；未闭合审计和租约均为零。
- 中文控制面板能清楚回答：谁在规划、谁在执行、谁在审阅、当前等待谁确认、依据是哪份证据。
- 全量测试、受控写入回归、doctor、公开扫描、差异检查和提交钩子全部通过。
