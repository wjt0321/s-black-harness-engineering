# 阶段 88：真实执行证据回收与人工审阅闭环

> 状态：已完成并归档
>
> 日期：2026-07-27
>
> 归档实施计划：`plans/2026-07-27-stage88-external-agent-evidence-human-review.md`

## 目标

在阶段87单工作项受控执行基础上，持久回收 Pi/OMP 的真实宿主事件，将通过安全校验的最终文本或 JSON 保存为机器本地不可变产物，并允许人工对精确绑定的执行尝试与产物提交“通过”或“要求修改”决定，为后续规划者、执行者、审阅者闭环提供事实基础。

## 已确认边界

- 真实产物只来自 Pi/OMP 最终回复，格式限 UTF-8 文本或合法 JSON。
- 不允许 Agent 指定、读取或回收任意项目文件路径。
- Pi/OMP 继续保持空工具；不开放文件、命令、网络或自动重试能力。
- 不新增数据库、常驻服务、跨 Agent 转发或并行派发。
- 所有机器运行态写入 `.runtime/`，不得进入 Git。

## 采用方案

采用“独立不可变证据包 + 派生读取投影”。不改写协作计划，不把运行证据混入 reserved execution audit writer，也不只依赖一次性 CLI 输出。

固定目录：

```text
.runtime/external-agent-evidence/v1/
├── pending/<attempt_id>.json
├── attempts/<attempt_id>/manifest.json
├── artifacts/<sha256>.<txt|json>
└── reviews/<review_id>.json
```

- `pending` 是安全扫描后、终态审计闭合前后的可恢复事务记录。
- `manifest.json` 是一次执行尝试的不可变证据清单。
- `artifacts` 按内容摘要寻址；同摘要同内容可复用，摘要冲突失败关闭。
- `reviews` 是不可变人工审阅记录；同一审阅编号只允许成功创建一次。
- 读取模型扫描固定目录并派生事件、产物、审阅和当前工作项状态，不维护可被覆盖的总状态文件。

## 宿主事件协议

Pi/OMP 扩展为每次已领取请求生成最多八条固定事件：

1. `request_claimed`
2. `host_turn_dispatched`
3. `host_turn_started`
4. `host_turn_completed`
5. `host_turn_blocked`
6. `host_turn_timed_out`
7. `host_session_closed`

每条事件只含序号、固定类型、UTC 时间和固定失败码；不得携带提示词、会话原文、环境变量、工具参数或任意说明。Python 侧使用版本化 JSON Schema 校验身份、数量、连续序号、允许的状态路径和时间非倒退。无效事件链使执行在后校验阶段失败关闭。

## 产物语义

- 每次成功执行最多生成一个输出产物。
- 保留最终回复的原始 UTF-8 字节；合法 JSON 使用 `.json`，否则使用 `.txt`。
- 内容摘要、字节数、媒体类型由 Harness 重新计算，不信任宿主声明。
- 产物清单记录协作文件、工作项、执行尝试、目标智能体、请求编号、计划摘要、输出摘要、预期产物类别和审阅门禁。
- 若工作项只有一个预期产物类别，则将其记为声明类别；多个类别时仅记为通用执行结果，不冒充已生成任意项目文件。

## 人工审阅

当工作项 `review_required=true` 时，成功归档后派生状态为“等待人工审阅”。必须恰好存在一个包含该工作项的审阅门禁，否则执行预览失败关闭。

人工决定只有：

- `approve`：审阅通过，产物派生为已验证，执行尝试派生为已完成。
- `request_changes`：要求修改，保留旧产物，执行尝试派生为要求修改；后续必须使用新的执行尝试。

审阅采用预览/确认两步：预览绑定协作计划摘要、工作项、尝试编号、门禁、产物摘要、决定、意见摘要和证据清单摘要；提交时必须携带同一一次性确认摘要和 `--commit`。任何绑定内容漂移都会失败。审阅意见限制长度、禁止空字符并执行敏感信息扫描。

## 事务与恢复

1. 校验宿主结果和事件。
2. 扫描输出并写入不可变 `pending` 事务。
3. 写唯一执行终态审计。
4. 将产物和清单原子归档。
5. 写后重新读取并校验摘要。
6. 删除对应 `pending`。

若第4或第5步失败，保留 `pending`，读取模型显示“证据待恢复”，并允许固定恢复入口在不重新调用 Pi/OMP 的前提下完成归档。旧证据和旧审阅永不覆盖或删除。

## 用户界面

新增稳定 CLI 读取与写入入口，并提供确定性 JSON：

- 查看执行证据：按执行尝试编号读取真实事件、产物摘要和审阅状态。
- 恢复待归档证据：固定恢复同一尝试，不重新执行 Agent。
- 提交人工审阅：先预览，再用一次性确认摘要提交。

中文控制面板增加真实执行时间线、结果产物、等待审阅、审阅通过、要求修改和安全失败原因。控制面板保持只读。

## 明确不做

- 任意项目文件产物回收；
- Agent 文件工具、通用命令或网络访问；
- 自动审阅者；
- 自动规划和自动派发；
- 自动重试、有限并发、取消或跨 Agent 转发；
- Harness 启停外部宿主。

## 验收

- Pi 和 OMP 各完成一次真实事件与产物归档。
- 至少完成一次人工通过和一次要求修改的真实/受控验收。
- 重启 CLI 后仍可恢复证据和审阅结果。
- 事件、产物、审阅或确认绑定篡改均失败关闭。
- 敏感信息不进入证据包。
- 阶段87回归、全量测试、doctor、公开扫描、差异检查和提交钩子全部通过。
## 最终实现

- 新增 `external-agent-single-work-item-result/v2`，校验固定宿主事件、连续序号、时间顺序、终态路径、结果上限与输出摘要；
- 新增不可变证据存储 `agent_runtime/external_agent_evidence_store.py`，固定管理 pending、执行清单、内容寻址产物和人工审阅记录；
- 单工作项成功路径先准备 pending，再写唯一 terminal audit，最后完成证据归档；归档失败保留 pending；
- 新增 `single-work-item-evidence`、`single-work-item-evidence-recover`、`single-work-item-review` 三组 CLI；
- 人工审阅计划绑定尝试编号、协作计划、工作项、门禁、产物、清单、决定和意见摘要；
- 中文控制面板新增“真实执行证据 / 人工审阅”只读区段；
- 对宿主状态发布与评估时间之间的窄竞争只在提交前做有限重读，不放宽全局未来时间拒绝、状态有效期或任何执行权限。
