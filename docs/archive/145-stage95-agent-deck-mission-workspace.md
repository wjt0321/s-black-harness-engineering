## 这次真正增加了什么

用户现在可以在 Agent Deck 中写下想完成的目标，点击“生成协作草案”，立刻看到一份通俗的团队接力建议：

1. Pi 分析目标并规划；
2. OMP 实现并验证；
3. Pi 审阅并汇总。

这让“主 Agent 未来怎样安排团队”变得可见、可理解。但页面会明确显示这仍是**待正式派发的浏览器草案**：它只保存在当前浏览器会话，没有写入任务账本、没有调用主 Agent、没有启动 Pi/OMP，更没有批准、取消、恢复或命令执行入口。

同时，工作台新增“已登记任务”队列：它从 Harness 既有任务账本只读投影真实任务，让用户能区分“我刚刚构思的目标”与“系统已经正式记录的任务”。

## 安全实现

`agent-deck/read-model/v1` 新增可选 `task_queue`，最多 12 项。每项只包含：

- 任务 ID；
- 经既有策略 secret scan 后的有界标题；
- 原始账本状态及后端给出的中文状态标签；
- 是否已分配；
- 更新时间。

任务的 summary、evidence、artifacts、路径、原始目标和其他自由文本一律不会进入 Agent Deck 快照。无效 ID/状态、超长或换行标题、secret scan 命中的标题都会失败关闭为“任务内容已隐藏”。前端不会重新判断任务是否能执行。

前台继续满足：`read_only=true`、`ui_dispatch=false`，没有新增 CLI operation、writer、宿主协议、网络 adapter、监听端口、数据库、后台服务、自动重试、并发或自动批准。

## 接下来还缺的关键能力

这一步故意没有假装“主 Agent 已经自动完成任务”。真正做到“你交代一句话，主 Agent 自动拆分、受控提交、调度团队、最后给你验收”，下一切片必须独立设计**受控任务提交和真实主 Agent 规划**：它需要让前台草案安全进入 Harness 账本，并严格复用审批、状态预检、lease、审计、证据和最终人工验收，而不能让网页获得任意执行权限。
