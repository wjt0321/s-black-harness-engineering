# 阶段 95 — Agent Deck 任务工作区设计

> 状态：已由用户于 2026-07-29 授权自主实施。
> 目标：把 Agent Deck 从“查看成员和历史链路”的看板，升级为用户能交代目标、理解协作建议、看到真实任务队列的工作区；本切片不新增任何宿主执行权。

## 用一句话说明

用户把目标写进工作台后，页面会生成一份**明确标为未派发的协作草案**：Pi 负责理解和规划、OMP 负责实现和测试、Pi 负责审阅。与此同时，工作台展示 Harness 账本中真实存在的任务及其状态。用户能分清“我正在构思的任务”和“已经被系统正式记录的任务”，不会把前台草案误认为 Agent 已经开始工作。

## 选择的方案

### A. 只做浏览器草稿

优点是最小；缺点是用户看不到任何真实任务上下文，仍像一个单独输入框，无法形成工作台。

### B. 浏览器协作草案 + Harness 安全任务投影（采用）

浏览器将当前目标保留在 `sessionStorage`，只在当前会话中生成固定协作建议；Python read model 同时从既有任务账本投影有界、安全的任务队列。两者都不执行、不写账本、不打开网络。

这样用户已经获得“交代目标 → 看懂团队怎样接力 → 对照真实任务队列”的核心体验；下一切片可在独立授权后为草案设计受控提交与主 Agent 规划，而不是把网页直接接到命令执行。

### C. 现在让网页直接启动 Pi/OMP

拒绝。它会让浏览器绕过既有一次性确认、lease、状态预检、审计和最终人工决定，也会把通用自然语言输入变成任意执行入口。

## 范围

### 1. 安全任务队列投影

`agent-deck/read-model/v1` 新增可选 `task_queue`：最多 12 个任务，只允许以下安全字段：

- `task_id`；
- `status`；
- `status_label_zh`；
- `assignee_label_zh`；
- `updated_at`；
- `title_zh`，仅在字符串长度有界且通过既有策略 secret scan 时显示；否则显示“任务内容已隐藏”。

来源仅是既有 `tasks/tasks.jsonl` 的只读加载器。投影不读取 artifacts、evidence、summary、message、原始目标、路径或其他自由文本；失败、缺失或不安全字段均退化为安全占位，不阻塞其余快照。

### 2. 任务草案与协作建议

`TaskComposer` 改为“生成协作草案”。输入仍只保存在浏览器 session，长度上限 1,200 字；生成后页面显示：

1. 任务目标摘要；
2. 三步接力建议：Pi 分析规划 → OMP 实现验证 → Pi 审阅汇总；
3. 每步均标为“待正式派发”；
4. 明确说明该草案没有写入账本、没有调用主 Agent、没有启动 Pi/OMP。

这是一份**透明的协调模板**，不是伪装成真实主 Agent 输出。用户能够清楚理解未来主 Agent 将承担的职责，但不会被误导为已有自治执行。

### 3. 前台任务工作区

新增“任务工作区”组件，按“当前草案 / 已登记任务”显示。真实任务队列的数据只来自 runtime snapshot；fixture 也必须显式标注为演示数据。任务状态使用中文映射，不从前端重新推断执行资格。

## 不变量与停止线

- schema 版本保持 `agent-deck/read-model/v1`，新增字段为可选兼容扩展；
- `guarantees.read_only=true`、`ui_dispatch=false` 不变；
- 不新增 CLI operation、writer、宿主协议、监听端口、网络 adapter、数据库、自动重试、并发或后台服务；
- 不显示未扫描的账本文本，不读取凭据，不回显 secret scan 命中内容；
- 前端不能出现“立即执行”“批准”“取消”“恢复”或命令桥接；
- 浏览器草案不等于任务账本记录，更不等于 Agent 已工作。

## 验收

1. Python 测试证明安全任务投影有界、标题通过 secret scan、命中或无效标题被隐藏、不会引入原始任务摘要/证据；
2. React 测试证明任务草案生成三角色建议但不 dispatch，且真实队列状态按 snapshot 原样展示；
3. 真实 runtime 快照包含当前既有账本任务，构建产物包含该快照，`ui_dispatch=false`；
4. 全量 Python/前端测试、doctor、public scan、pre-commit 和 `git diff --check` 通过。

## 后续而非本切片

只有用户再次明确授权时，才设计：把草案受控提交到任务账本、让真实主 Agent 对目标提出有界计划、将计划映射到已登记工作卡，或接入更多 CLI Agent。它们都必须另行设计确认，且复用 Harness 的确认、审计、证据与人工验收边界。
