# 02 — 路线图

> 本页只记录能力包、当前里程碑和下一候选。逐阶段历史已归档到 `docs/archive/`。

## 已完成能力包

### 1. 安全边界与账本内核

- 策略、结构校验、敏感信息扫描、路径与动作门禁。
- 任务/事件账本、运行报告、执行信封。
- 试运行、计划摘要、受控追加、写后校验和失败回滚。

### 2. 编排控制面

- 基于事实源的智能体与适配器注册表。
- 能力路由、决策轨迹、配置/工作流/契约校验。
- 任务、运行、审批、产物与恢复链路读取模型。
- 静态只读中文控制面板和一次性生产/消费/宿主管道。

### 3. 受控执行基础设施

- 单机租约与可执行文件信任绑定。
- 开始/终止审计、未闭合尝试恢复、审计第二版。
- Windows Job Object 进程树约束、有界标准输出/错误输出和安全投影。

### 4. 多智能体插座与协作计划

- Pi、Kimi Code、Claude Code、OMP 与 QwenPaw 统一投影为智能体插座。
- 支持角色、工作项、依赖、交接、预期产物和审阅门禁。
- 人工计划编辑、确认、导出、样例运行、当前待办和不可执行命令候选均已具备。

### 5. 外部智能体状态与单工作项执行

- 统一外部智能体适配器契约、失败矩阵和固定原子状态快照。
- Pi/OMP 项目级状态发布、15 秒有效期、严格身份/生产者绑定和中文界面映射。
- 一次性确认、固定信箱、空工具与空闲检查、有界结果、敏感信息扫描和完整审计。
- Pi/OMP 真实单工作项验收均已通过。

### 6. 真实证据与人工审阅

- 回收固定、连续、无原文的真实宿主事件链。
- 将安全的最终文本或 JSON 保存为不可变内容寻址产物和执行清单。
- 使用 pending 事务支持不重新调用 Agent 的固定证据恢复。
- 人工审阅精确绑定执行尝试、产物、门禁、清单和意见摘要，仅允许“通过”或“要求修改”。
- 中文 CLI 和只读控制面板可恢复展示事件、产物与审阅状态。
- Pi“通过”和 OMP“要求修改”两条真实路径均已验收。

## 当前真实操作

- 固定 Git 状态：固定 `git status --short --branch`。
- 固定 Pi 打印：固定 `pi --print --no-session --no-tools <prompt>`。
- 固定单工作项派发：只向用户已打开的 `pi-local` 或 `omp-local` 派发一个经过确认的工作项。

三项操作均要求显式提交、固定输入、单机租约、started/terminal 审计和有界公开输出。单工作项派发不启动宿主、不开放工具、不自动重试或并行；证据归档和人工审阅不会自动触发新执行。

## 当前停止线

- 不开放通用 shell、任意适配器执行或 POSIX fallback。
- 不开放网络适配器、服务、数据库或自动后台执行。
- 不开放 Pi/OMP read/write/edit/bash 或 MCP 工具。
- 不由 Harness 启动、关闭或重启外部智能体。
- 不自动重试、不并行派发、不跨 Agent 自由转发。
- 不允许 Agent 指定任意项目文件作为产物。
- 人工审阅结果不会自动生成修改指令、自动批准或触发下一次执行。
- 只读状态、证据读取、预览和人工计划确认都不能单独解释为执行授权。

## 阶段 89 有限自动串行闭环（已完成并归档）

归档事实源：`archive/138-stage89-bounded-planner-executor-review-design.md`。

- 一个有界目标在一次启动确认后自动按“规划者 -> 执行者 -> 审阅者”串行完成；操作者只作启动与最终业务决定；
- 仅允许 Pi/OMP 两种交替拓扑；每个角色前使用固定两秒状态稳定窗口，再做一次 fail-closed 的新鲜状态读取；
- 规划候选与审阅建议是严格、有界、已扫描 JSON；不受信执行文本不进入审阅提示；
- 失败、状态漂移、schema 不匹配、证据待恢复和“要求修改”均停止；没有自动重试、自动修改或自动批准；
- 2026-07-28 已完成真实正反拓扑：正向 `Pi -> OMP -> Pi` 经最终人工决定为通过；反向 `OMP -> Pi -> OMP` 经最终人工决定为要求修改。失败路径也已确认会写入 `stop` 且不派发后续角色。
